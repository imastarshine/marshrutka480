# Модель защиты и границы

Проект рассчитан на небольшой сервер комнат с одним процессом FastAPI.
Браузер игрока и каждое входящее сообщение считаются недоверенными.
Хозяин ОС, файлов базы и серверного процесса считается доверенным.

## Оригинальная игра с друзьями: city

Новый интерфейс создаёт только комнаты `mode: "city"`. Своя маршрутка,
NPC, пассажиры и карьера рассчитываются оригинальным движком в браузере.
Сервер передаёт положение других игроков, но не считает эти данные
доверенным результатом. Комнаты city всегда `ranked: false`; деньги,
пассажиры и очки не принимаются и не сохраняются в серверный рейтинг.

Пакеты `pose` проходят строгую проверку полей, конечности чисел, диапазонов,
возрастающего seq и допустимого перемещения между сообщениями.
Команда `spawn` позволяет начать новый локальный рейс не чаще раза в 2 с.
Это ограничивает ошибочные пакеты, но не является защитой от читов:
клиент способен подделывать допустимое положение и выбранную модель.
Столкновений между игроками и общей серверной экономики в city нет.
При обрыве связи свой рейс продолжается локально, чужая маршрутка замирает
и отображается полупрозрачной до переподключения или удаления участника.

## Чему доверяет старый рейтинг arcade

Старая серверная симуляция сохранена для совместимости API и ранее
записанных результатов. Новый интерфейс её не запускает.

Сетевой клиент отправляет нажатия `up/down/left/right`, монотонный `seq`
и служебные команды. Координаты, скорость, дистанция, длительность,
пассажиры, деньги и результаты рассчитываются только сервером.
Неизвестные поля и типы отклоняются Pydantic. Endpoint загрузки очков
от браузера отсутствует.

Симуляция выполняет фиксированные шаги 0,05 с. Количество присланных пакетов
не ускоряет время: новое управление только заменяет прежнее.
Сервер проверяет положение у остановки, скорость, 1,5 с посадки,
общий остаток пассажиров и набор уже обслуженных остановок.
Результат сохраняется только после завершения серверной смены и хотя бы
одной обслуженной остановки. В SQLite стоит UNIQUE(round_id, user_id).

Это защищает от отправки «миллиарда рублей», телепорта и накрутки времени
пакетами. Автоматический водитель, который посылает допустимые нажатия,
остаётся возможным. CAPTCHA, антибот-модерация и обнаружение сговоров
не реализованы. Одиночная игра управляется клиентом и в этот рейтинг не входит.

## Аккаунты и сессии

Пароль хешируется `hashlib.scrypt` с N=32768, r=8, p=3 и 16-байтовой
случайной солью. Сравнение — `hmac.compare_digest`. Параметры соответствуют
одному из вариантов OWASP с 32 MiB памяти. Одновременно вычисляются не более
двух хешей; отказ от HTTP-запроса не освобождает слот, пока вычисление не закончено.

Сессия — случайный 256-битный непрозрачный токен. В SQLite записывается
его SHA-256, а не исходное значение. Клиент держит токен в памяти вкладки,
отправляет HTTP-заголовком `Authorization` и первым сообщением WebSocket.
В query string, localStorage, sessionStorage и cookie токен не попадает.

Срок — 8 часов, до пяти сессий аккаунта; активный игровой сокет — один.
Выход отзывает текущий токен и закрывает связанный сокет. Истечение
проверяется при HTTP-доступе и командах WS, активные соединения дополнительно
проверяются периодически. При обновлении страницы требуется новый вход.

Нет автоматического восстановления забытого пароля, MFA, email-проверки,
OAuth и интерфейса администратора. Никнеймы и лучшие результаты публичны.
Нельзя использовать токены или пароль в логах, аналитике и URL.

## Ввод, доступ и ресурсы

| Контроль | Значение по умолчанию |
|---|---|
| Origin | Точное разрешённое множество; production только HTTPS |
| Host | Точное разрешённое множество, без wildcard |
| Пароль | 10–128 символов |
| Имя | 3–24 символа, ограниченный алфавит, casefold-уникальность |
| HTTP API | 120 запросов/мин/IP |
| Вход/регистрация | Общий лимит 10/мин/IP; регистрация дополнительно 5/10 мин/IP |
| Попытки одного имени | 20/мин |
| Создание комнаты | 12/мин/аккаунт |
| Попытки входа в комнату | 20/мин/аккаунт |
| HTTP-тело | 8192 байта, в том числе реальный chunked body; timeout 10 с |
| WS-сообщение | 2048 байт; только текстовый JSON-объект |
| WS-авторизация | Первое сообщение за 5 с, Origin проверяется до accept |
| WS-поток | 60 сообщений/с/аккаунт; клиент city посылает положение 20 Гц |
| Новые WS | 20/мин/IP; не более 4 незавершённых авторизаций с IP |
| Сокеты сервера | 128 включая незавершённую авторизацию |
| Комнаты | До 64; в каждой до 8 участников |
| Нет данных WS | Timeout 35 с; клиентский heartbeat каждые 3 с |
| Нет управления | В arcade торможение после 0,5 с; в city последнее принятое положение |
| Переподключение | Место сохраняется 20 с, клиент пытается около 18 с |
| Очередь отправки | 3 сообщения; старые снимки вытесняются свежими |
| Отправка медленному клиенту | Timeout 2 с |

Счётчики частоты и комнаты хранятся в памяти одного процесса. Они
сбрасываются при перезапуске; распределённого лимитера здесь нет.
Непубличная комната скрыта из общего списка и доступна по случайному коду.
Код — приглашение, а не второй пароль: любой авторизованный игрок,
получивший код, может войти при наличии места.

В arcade разрешение запуска проверяет сервер по `host_id`; city доступна
для поездки и подключения сразу после создания. При каждой команде
проверяется действующее соединение и членство. Чужой комнате управление
передать нельзя. Повторный seq отклоняется, три нарушения схемы закрывают
сокет. Дублирующий сокет аккаунта отклоняется. Ушедший игрок не получает
зачёт незавершённого рейса.

## База и фронтенд

SQL параметризован; ключи сортировки заданы кодом. SQLite использует WAL,
foreign_keys, busy_timeout, короткие транзакции и явное закрытие соединений.
Файл базы получает права 0600 там, где ОС поддерживает POSIX-права.
Резервные копии тоже содержат данные аккаунтов и требуют защиты.

StaticFiles публикует только `web/`, поэтому база, `.env`, исходники backend
и backup не становятся веб-ресурсами. Пользовательские строки попадают
в DOM через `textContent`, а в игровой экран — через Canvas. HTML не исполняется.

FastAPI добавляет CSP (`script-src 'self'`, `style-src 'self'`,
`connect-src 'self'`, запрет object/embed/framing), X-Content-Type-Options,
X-Frame-Options, Referrer-Policy, Permissions-Policy, no-store для API;
production добавляет HSTS. При размещении `web/` на GitHub Pages заголовками
статического хостинга управляет GitHub, а не FastAPI.

## Что остаётся ответственностью эксплуатации

- TLS/WSS, firewall и обновления ОС/зависимостей.
- Доверие только конкретному reverse proxy, корректные реальные IP.
- Постоянный диск, ограниченный доступ к SQLite и резервные копии.
- Наблюдение за ошибками, диском и потреблением CPU/RAM; проверка реальной нагрузки.
- Защита от объёмного DDoS на стороне провайдера/proxy: лимиты приложения
  не остановят заполнение сетевого канала или распределённую атаку.
- Учет того, что владелец сервера может менять базу и результаты.

Тесты проверяют перечисленные свойства, но не являются обещанием полной
неуязвимости или независимым аудитом публичного production-сервера.
