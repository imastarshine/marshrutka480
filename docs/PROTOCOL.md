# Сетевой протокол v1

Все HTTP URL относительно `API_BASE` (пустая строка = этот же сервер). JSON UTF-8.
Авторизация: `Authorization: Bearer <token>`. Токен хранится клиентом в памяти
и `sessionStorage` текущей вкладки; при восстановлении проверяется через `/api/auth/me`.
Ошибка HTTP: `{"detail":"понятный текст"}`. Pydantic 422 также может вернуть массив ошибок.

## HTTP

- `GET /api/health` → `{ok:true,version:"2.3.0-beta.1",protocol:1,features:[...]}`.
- `POST /api/auth/guest`, тело `{}` → `{token,expires_at,user:{id,username}}`;
  сервер выдаёт уникальный гостевой позывной без пароля. Не более 30 выдач за 10 минут с IP.
- `POST /api/auth/register`, `POST /api/auth/login`, тело `{username,password}` →
  `{token,expires_at,user:{id,username}}`. Имя 3–24, латиница/кириллица/цифры/`_-`; пароль 10–128 символов.
- `GET /api/auth/me` → `{user:{id,username}}`.
- `POST /api/auth/logout` → `{ok:true}`.
- `GET /api/leaderboard?limit=20` → `{entries:[{rank,username,score,stops,distance,completed_at}],mode:"online"}`.
  Лучший законченный рейс старого режима arcade. Комнаты city в рейтинг не входят.
- `GET /api/rooms` → `{rooms:[ROOM]}` (только публичные).
- `GET /api/city` → `{room:ROOM}` — постоянный общий город `IRKUTK`.
- `POST /api/city/join`, тело `{}` с Bearer → `{room:ROOM}` — вход в общий город.
  При выходе всех участников он сохраняется. После перезапуска в него можно войти заново.
- `POST /api/rooms`, тело `{name:"Вечерний рейс",public:true,max_players:4,mode:"city"}` → `{room:ROOM}`.
  Комната создаётся с владельцем-участником. max_players 1–8. Непубличная доступна по коду.
  mode: `city|arcade`; по умолчанию arcade для совместимости старых клиентов.
- `POST /api/rooms/CODE/join`, тело `{}` → `{room:ROOM}`.
- `POST /api/rooms/CODE/leave`, тело `{}` → `{ok:true}`.

`ROOM = {code,name,public,mode,shared,max_players,host_id,status,players:[{id,username,color,number,connected,state}],count}`;
У общего города `shared:true`, `max_players:null`, `host_id:0`; численного лимита
участников нет. Прочие комнаты имеют обычный численный `max_players`.
status: `waiting|countdown|running|finished`. City сразу running и допускает поздний вход.
Arcade допускает новых участников только в waiting/finished.

## WebSocket

`ws(s)://<API host>/ws`, обязательный разрешённый `Origin`.
В течение 5 секунд отправить `{type:"auth",token:"...",room:"ABC234"}`.
Сервер отвечает `{type:"welcome",player_id:1,protocol:1}`. Токен не передаётся в URL.
Один активный сокет на аккаунт. После обрыва можно повторить auth в течение 20 секунд,
чтобы продолжить тот же рейс с теми же данными. Вход через HTTP join повторять не требуется.

## City: оригинальный городской движок

### Отчёт об ошибке и бесплатное восстановление

`POST /api/bug-reports` с обычным Bearer-токеном аккаунта или гостя принимает
`version, route, edge, reverse, wx, wy, offset, lateral, angle, speed, state`,
необязательный `collision_id`, до 20 `nearby_npcs` (`id, edge, reverse, wx, wy, speed`)
и до 12 `signals` (`node, state, distance`). Лимит — один отчёт за 10 секунд на игрока.
Ответ `201 {id}` подтверждает сохранение. GPS вычисляется сервером из `wx/wy`.
Отчёты хранятся в `bug-reports.sqlite3` рядом с основной базой, переживают обновления.

Клиент бесплатно восстанавливает игрока сразу, сохраняя рейс; отправка отчёта
не блокирует движение. При недоступном сервере очередь сохраняется в браузере.
Восстановление не удаляет общие NPC и использует обычное подтверждение `spawn`.

### Положение и общий мир

Новый интерфейс использует только этот режим. Своя физика работает локально
с шагом 60 Гц; 20 раз/с клиент отправляет:

```json
{"type":"pose","seq":1,"wx":0,"wy":-250,"lateral":0,"angle":0,
 "speed":6,"jump":0,"door":0,"braking":false,"bus":"gazel",
 "route":"480","state":"play","street":"ул. Ленина","edge":"osm-way-..."}
```

В 2.3 `wx/wy` — фактический центр автобуса в общей карте, x на восток, y на юг.
`angle` — радианы по часовой стрелке от севера; новые клиенты передают `lateral:0`.
Для старых клиентов остаётся совместимость с позой на оси улицы:
центр `(wx + cos(angle)*lateral, wy + sin(angle)*lateral)`.
Скорость в пикселях за исходный шаг игры, двери 0..1, jump в пикселях.
Модель, маршрут и состояние ограничены исходными значениями игры.
`edge` — ID исходного дорожного ребра для диагностики; он больше не выбирает
сцену и не используется для переноса машины на другую нарисованную улицу.
Числа должны быть конечными; лишние поля, включая деньги, запрещены.

Сервер проверяет членство, seq и предел перемещения. При отказе возвращает
`{type:"correction",pose:последнее_принятое_положение}`. Клиент показывает
сообщение; свою маршрутку сетевой снимок не перемещает.

При начале нового рейса отправляется `{type:"spawn"}` (не чаще раза в 2 с).
Сервер подтверждает `{type:"spawned"}`; только после подтверждения клиент
начинает передавать новые положения. Ответ `{type:"spawn_wait",retry_ms}`
просит повторить запрос после задержки, без отправки новой позиции до подтверждения.
После переподключения текущее положение также подтверждается через spawn.
`ping` каждые 3 с, `horn` не чаще раза в 2 с,
`leave` работают как ниже. Команда `start` не нужна.

Снимки приходят 10 раз/с:
`{type:"state",room:ROOM,players:[CITY_PLAYER],seed,server_time,started_at,tick,
results:[],ranked:false}`.
В версии с общим трафиком снимок также содержит
`world:{authoritative_traffic:true,version:1}`, `traffic_server_time` и `traffic`.
`traffic` — полный список ближайших к получателю серверных машин на текущем тике:
`{id,wx,wy,angle,lateral,speed,color,braking,w,h,edge,reverse}`.
Для NPC 2.3 `wx/wy` также означает центр кузова, `lateral:0`; повороты
передаются по непрерывной дуге. Новые машины включаются в снимок в радиусе
3000 единиц, уже видимые сохраняются до 3800. Создание запрещено ближе
2200 единиц от любого наблюдателя, удаление — ближе 5000.
Координаты и скорость имеют те же единицы, что и позы игроков. Состояния машин
считаются один раз на сервере комнаты с частотой 20 Гц; различается только
дальность выдачи, поэтому в пересекающихся областях совпадают ID и положения.
Клиент интерполирует эти снимки и отключает локальное создание обычных и
поперечных машин. При потере связи последнее состояние замирает.
`CITY_PLAYER` содержит `id,username,color,number,connected,pose_time` и поля pose;
`pose_time` — серверное время последнего принятого положения, Unix-миллисекунды.
`room.players` содержит только облегчённый список участников, без дублирования координат.
до первого положения содержит только `state:"menu"`.
Номер и цвет назначает сервер; цвета повторяются каждые восемь номеров.
Чужие маршрутки отображаются из буфера снимков с задержкой 150 мс и короткой
экстраполяцией при задержке пакетов. Своя маршрутка использует локальный ввод.
Общее время и seed задают фазы светофоров. Повороты, двери, прыжки,
положение на дороге и метки на миникарте отображаются исходным рендерером.

Пассажиры и прогресс карьеры локальные. Результаты city не загружаются
в таблицу arcade; server не подтверждает клиентскую выручку.
При выходе из комнаты игрок продолжает свой одиночный рейс.

## Arcade: сохранённая совместимость

Этот формат обслуживает старые клиенты. Новый интерфейс его не использует.

Клиент → сервер:

- `{type:"input",seq:1,up:true,down:false,left:false,right:false}` до 30 раз/сек. seq строго возрастает в рамках соединения.
- `{type:"start"}`: владелец запускает смену (можно один), 3 секунды отсчёта; также начинает новый рейс после finished.
- `{type:"ping",t:12345}` → `{type:"pong",t:12345}`. Посылать каждые 10 секунд.
- `{type:"horn"}` → `{type:"horn",player_id:1}` всем, не чаще раза в 2 секунды.
- `{type:"leave"}`: покинуть комнату.

Сервер → клиент:

- `{type:"error",detail:"..."}` — отказ операции; критические нарушения закрывают соединение.
- `{type:"state",room:ROOM,tick:123,time_left:179.3,countdown:0,street:"ул. Ленина",
  players:[PLAYER],npcs:[NPC],stops:[STOP],results:[RESULT],server_time:1234567890}`.

`PLAYER = {id,username,color,x,z,speed,score,stops,distance,connected,invulnerable,boarding,next_stop,street}`.
`next_stop` — целое ID ближайшей ещё не пройденной остановки, `boarding` — прогресс 0..1.
`NPC = {id,x,z,speed,color}`.
`STOP = {id,name,z,waiting,street}`.
`RESULT = {id,username,score,stops,distance,qualified}`; results заполнен при finished.

## Координаты и правила

Холст 640×760. Дорога x=78..522, карман справа до590. x игрока — **центр** автобуса,
z — абсолютное расстояние вперёд в пикселях. Экранная позиция центра y=600-(z-self.z).
Автобус 56×116. NPC 50×92. Справа по ходу, встречка x<300.
Вперёд +z; скорости в px/сек. Верхняя скорость 600px/сек (70км/ч при масштабе оригинала).
Старт x=411, игроки слегка разнесены по z. Руль меняет x; повороты в этом режиме не нужны.
Общие машины, остановки и пассажиры определяются сервером. Столкновение = штраф и замедление,
не конец смены. Контакт автобусов не повреждает игроков (совместный рейс без тарана).
Остановка каждые 1800px, первая z=1000. Для посадки центр x>=535, |z-stop.z|<=90,
скорость<=18px/сек; 1.5 секунды обслуживания. За пассажира 60₽, за остановку +40₽.
Один игрок обслуживает каждую остановку один раз; общий запас пассажиров ограничен.
Пройденные остановки вернуть нельзя. Все игроки равны, улучшения одиночной игры не влияют.
Смена 180 секунд. В рейтинг попадает завершённый рейс с >=1 обслуженной остановкой.
Клиент не отправляет координаты, результаты, время, пассажиров или деньги.
Исчезнувший клиент тормозит после 0.5 секунды без input. Пауза не останавливает общий мир.
Мир и физика20Hz, снимки10Hz. Клиент интерполирует снимки, не рассчитывает зачётные результаты.

Предел входящего WS сообщения 2048 байт, потока60 сообщений/сек; допускается heartbeat.
Закрытия:4001 auth,4003 forbidden,4004 room missing,4008 timeout/rate limit,
4009 duplicate connection,1009 too large,1008 protocol violation.
Комнаты находятся в памяти одного процесса; результаты и аккаунты — в SQLite.
