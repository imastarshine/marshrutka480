> **Обновление 2.3.0-beta.4:** после просьбы пользователя тестовые наборы не запускались.
> Результаты ниже относятся к предыдущей версии 2.1.1 и не подтверждают новую
> единую мировую карту, симуляцию NPC, GPS и новую модель пешеходных переходов.
> Проверен синтаксис изменённых JS/Python-файлов; игровой и нагрузочный прогоны
> новой версии не проводились. Импорт исходных данных
> выполняет собственные проверки наличия координат и связности перед экспортом.

Дата: **11 ноября 2026**. Проверена игра после обновления географии Иркутска:
офлайн-клиент `index.html` + `js/`, сетевой клиент `web/` и сервер `server/`.
Оба клиента используют одинаковые данные города и игровой движок.

## География и движение: 11 проверок Node — OK

```bash
node tests/city_topology.test.js
```

Без npm-зависимостей проверены:

- совпадение движка и порядка загрузки файлов обоих клиентов;
- связность конечного графа дорог и существование концов каждого участка;
- непрерывные пути маршрутов **480, 80 и 33**, включая обратные направления;
- порядок и привязка **198 остановочных записей** к участкам и направлениям;
- реальные конечные остановки и отсутствие вымышленной обратной половины
  кольцевого маршрута 80;
- старт каждого маршрута на своей улице, миграция купленных маршрутов
  10/83 → 80 и 112 → 33 с сохранением денег, улучшений и автобуса;
- запрет поворота вдали от перекрёстка, через подставной узел или
  в отсутствующий съезд; сохранение общей точки улиц при повороте;
- остановка у обязательного поворота, граница заднего хода и сохранение
  полного пройденного расстояния при прямом переходе на соседний участок;
- неподвижная привязка остановок к своим улицам без дублирования и
  переноса остановок за автобусом на другую улицу.

Отдельный сценарий обычным циклом `update()` и управлением газом/рулём
прошёл **все 135 переходов** между участками трёх маршрутов: **0 ошибок**.
Прямой вызов `startTurn()` в этом сценарии не используется. Движение NPC
и случайные помехи отключены, чтобы проверить проходимость самой схемы.

## Сервер: 59 тестов — OK

```bash
cd server
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Полный запуск: **59 tests, OK**, Python 3.14.
В набор входят 51 проверка аккаунтов, хранения, HTTP/WS-ограничений, комнат,
переподключения и старой серверной симуляции arcade, а также 5 тестов city:

- вход во время поездки, передача оригинальной модели, маршрута и гудка;
- строгая схема, запрет NaN/лишних полей, предел скорости и резких перемещений;
- сохранение положения и оформления игрока при переподключении;
- освобождение места и номера участника после выхода;
- отсутствие записи клиентских очков в рейтинг.

Ещё 3 проверки охватывают версионирование по содержимому файлов,
некэшируемый HTML при GET/HEAD и отказ подготовки релиза без обязательного
HTML или локального ресурса.

Хеши паролей, сессии, ограничения запросов, проверки Origin и Host,
изоляция комнат и закрытие недействительных соединений сохранены.

## Браузер: 8 интеграционных сценариев — OK

Google Chrome, Playwright, настоящий HTTP/WebSocket через Uvicorn.
Используются временная SQLite-база и два независимых контекста браузера.

1. Регистрация двух водителей через интерфейс, создание комнаты, поздний вход.
   Проверены исходный Game, сюжет и повороты, полная высота и центр холста
   на экране 1440×1000.
2. При задержке исходящих pose-пакетов на **350 мс** своя маршрутка начинает
   движение за **25 мс** (два локальных кадра в последнем запуске).
   Это проверка отсутствия ожидания сети, не обещание универсального времени отклика.
3. Второй клиент получает движение маршрутки, отображает её на исходной дороге
   и видит подписанную метку на миникарте. Газ отпускается после 200 игровых
   пикселей и включается тормоз: сценарий сохраняет автобус в кадре независимо
   от задержек команд автоматизации под нагрузкой.
4. Анимация поворота передаёт направление, реальную улицу и мировые координаты.
   Тест выбирает связанный перекрёсток из пути маршрута, ставит автобус
   перед ним и вызывает `startTurn()` с разрешённой стороной. Координаты
   после поворота совпадают с общим узлом двух участков.
5. Имитированный обрыв WebSocket восстанавливает соединение и участие в комнате,
   сохраняя текущий локальный рейс.
6. «Одиночная игра» отключает комнату, сохраняет текущую маршрутку и карьеру.
   Внешнее меню содержит только два режима; выбор не перезапускает рейс.
7. На телефоне 390×844 гараж, автопарк, маршруты и запуск доступны через
   исходные кнопки на холсте. Проверены сенсорная пауза и продолжение,
   прокрутка сетевой панели по нажатию, хедер с профилем и отсутствие
   залипания управления при вводе. В одиночном режиме сетевые формы скрыты.
8. В горизонтальной ориентации 844×390 нет горизонтального переполнения.
   Высокий экран 1280×1024 переключается на прокручиваемую страницу,
   чтобы боковое меню не перекрывало игру.

JavaScript-ошибок в консоли нет. Десктопный экран, диспетчерская и мобильная
страница проверены по снимкам. Сценарии и измерение записываются в
`test-results/city-browser-report.json`, снимки — в тот же игнорируемый каталог.

Повторить из корня (нужен установленный Google Chrome и свободный порт 18882):

```bash
python -m pip install -r requirements-browser.txt
python tests/browser_smoke.py
```

## Офлайн через file:// — OK

В отдельном контексте Google Chrome открыт корневой `index.html` через
`file://`, без HTTP-сервера. `city.js` загружается, создаётся граф города.
Проверен запуск и движение на всех трёх маршрутах: 480 начинает на улице
Ширямова, 80 — в Юбилейном микрорайоне, 33 — на улице Литвинова.
Во всех случаях координаты конечны, автобус движется, состояние остаётся
`play`, JavaScript-ошибок нет. Снимок: `test-results/offline-irkutsk-final.png`.

## Дополнительные проверки и пределы

- Синтаксис изменённых JavaScript-файлов проверяется `node --check`.
- Офлайн- и сетевой клиенты обновлены вместе; идентичность общих скриптов
  проверяется тестом Node, загрузка офлайн-клиента — отдельно через `file://`.
- Геометрия схематическая: кварталы растянуты под аркадную механику,
  близкие примыкания объединены. Это не навигационная карта или расписание.
  Источники и ограничения: [IRKUTSK_SOURCES.md](IRKUTSK_SOURCES.md).
- Docker-образ локально не запускался: Docker daemon отсутствует.
- Нагрузочное испытание и проверка всех мобильных браузеров не выполнялись.
- В city сервер передаёт положение игроков; NPC и карьера остаются локальными.
  Эти комнаты не используют рейтинг и не дают серверной гарантии против читов.
  Границы описаны в [SECURITY.md](../SECURITY.md).


## Обновление поверх сохранённого HTTP-кэша

`python tests/browser_cache_update.py` воспроизводит `CityGraph is not defined`
на обеих версиях: `utils.js` из 70ab315 остаётся в реальном HTTP-кэше,
а HTML и игровой код берутся из первой версии географии cf80612.
Затем обычный переход загружает исправленные адреса скриптов: игра запускается,
маршрутка едет, кошелёк, улучшения и автобус сохраняются. Кэш и localStorage
в проверке не очищаются. Дополнительно серверные проверки контролируют
изменение хеша при одинаковых размере/времени файла и ответы GET/HEAD.

Серверный HTML содержит хеш содержимого каждого JS/CSS в URL и отдаётся
с `Cache-Control: no-store`; ресурсы требуют перепроверки перед повторным
использованием. При следующем обновлении версии URL пересчитываются автоматически.
