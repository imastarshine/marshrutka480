## Браузер: 12 интеграционных сценариев — OK

Настоящий Chromium Headless Shell 141 с Playwright 1.56.0, HTTP и WebSocket
через Uvicorn. Клиенты открывались в независимых контекстах браузера,
вход и управление выполнялись через элементы интерфейса и нажатия клавиш.

1. Два аккаунта зарегистрированы через формы.
2. Создана комната, второй водитель вошёл по коду; запуск виден только ведущему.
3. Газ, руль, тормоз и выдержка остановки дали первому игроку 280 ₽ с сервера.
4. Второй клиент увидел тот же заработок, позицию и общий остаток пассажиров.
5. Имитированный обрыв сокета автоматически восстановился без потери результата.
6. Второй водитель самостоятельно доехал и обслужил общую остановку.
7. Завершение смены записало обоих водителей в постоянный рейтинг SQLite.
8. Токен не записался в localStorage/sessionStorage.
9. Сюжет и движение исходной одиночной игры продолжают работать.
10. На экране 390×844 доступны сенсорные кнопки, горизонтального переполнения нет.
11. Выход очищает аккаунт и комнату на клиенте.
12. Статический frontend на другом Origin успешно выполнил CORS-регистрацию,
    создание комнаты и WebSocket-авторизацию на отдельном backend.

В консоли браузера **нет JavaScript-ошибок**. Интерфейс просмотрен на
desktop 1365×1000 и мобильном экране 390×844.
Для ускорения интеграционного теста серверная смена была установлена в 22 с;
обычный запуск из .env использует неизменные **180 с**. Тест не принимает
клиентские очки и не подменяет состояние физики.

Повторить самостоятельно:

```bash
python -m pip install -r requirements-browser.txt
python -m playwright install chromium
python tests/browser_smoke.py
```

Нужны свободные локальные порты 18880 и 18881. Тест использует временную
базу; снимки и отчёт пишет в игнорируемый `test-results/`. Production-данные
не затрагиваются. Экранные имена из теста — фиктивные аккаунты.

## Предел проверки

Docker daemon в среде проверки отсутствует: контейнер и Compose проверены
как конфигурация, образ здесь не запускался. Не выполнялись публичное TLS-
развёртывание, длительное нагрузочное испытание, реальный DDoS, аудит всей
цепочки зависимостей или испытания всех мобильных браузеров. Проверка
отдельного Origin сделана на локальных HTTP-портах; публично нужны HTTPS/WSS.

Защита от подмены результата не означает защиту от ботов, которые посылают
допустимые нажатия. Эти границы также описаны в SECURITY.md.
