# Сервер Маршрутки 480

Здесь собраны серверный код, зависимости, конфигурации и тесты.
Интерфейс находится рядом, в `../web/`. Офлайн-версия в корне репозитория
отдельная: она не требует Python и подходит для GitHub Pages.

## systemd + nginx

1. Размести репозиторий в `/opt/marshrutka480`.
2. Создай системного пользователя `marshrutka` без интерактивного входа.
3. В этой папке создай `.venv` и установи `requirements.txt`.
4. Создай `data/` с владельцем `marshrutka:marshrutka` и правами `0700`.
5. Создай `.env` с правами `root:marshrutka 0640`:

```dotenv
M480_ENV=production
M480_DATABASE=/opt/marshrutka480/server/data/marshrutka.sqlite3
M480_ORIGINS=https://game.example.com
M480_HOSTS=game.example.com,localhost,127.0.0.1
M480_PROXY_IPS=127.0.0.1
PYTHONUNBUFFERED=1
PYTHONDONTWRITEBYTECODE=1
```

6. Установи `deploy/marshrutka.service` в `/etc/systemd/system/`.
7. Выполни `systemctl daemon-reload` и `systemctl enable --now marshrutka`.
8. Настрой nginx или Caddy на HTTPS с проксированием `/api/*` и `/ws`
   на `127.0.0.1:8000`. Примеры находятся в `deploy/`.

Замени `game.example.com` настоящим доменом или IP с доверенным TLS-сертификатом.
Origin содержит схему и хост, без пути и завершающего `/`.
Порт 8000 не публикуется наружу. Доверять proxy-заголовкам можно только
от явно заданного локального IP, не от `*`.

`web/config/runtime.js` по умолчанию использует тот же origin. Для отдельной
публикации `web/` укажи HTTPS-адрес API и добавь точный origin страницы в
`M480_ORIGINS`. Это не требуется для исходной офлайн-игры в корне.

## Docker

Из `server/`:

```bash
cp .env.example .env
# Заполни production-настройки.
docker compose up -d --build
```

Контекст сборки — корень репозитория; Dockerfile расположен в `server/`.
В образ попадают только backend, зависимости, launcher и `web/`.
Постоянный том подключается к `/app/server/data`. Одна реплика, один worker.
`docker compose down -v` удаляет данные и не используется для обновления.

## База и обновления

Перед обновлением, находясь в `server/`:

```bash
.venv/bin/python scripts/backup.py data/marshrutka.sqlite3
```

Backup API SQLite создаёт согласованную копию, включая WAL. Храни резервные
копии вне `web/`, с закрытым доступом. Не перезаписывай `.env` и `data/`
архивом исходников. При первом переходе со старой структуры скопируй базу
из корневого `data/` после остановки старой службы, сохрани оригинал для отката.

После установки зависимостей и тестов перезапусти службу. Открытые комнаты
закроются; аккаунты и сохранённые результаты останутся в SQLite.

```bash
.venv/bin/python -m pip check
.venv/bin/python -m unittest discover -s tests -v
systemctl restart marshrutka
curl --fail http://127.0.0.1:8000/api/health
```

## Комнаты оригинальной игры

**Общий город** доступен через `POST /api/city/join`, без приглашения и без
лимита размера комнаты. `POST /api/auth/guest` выдаёт гостевой позывной и
обычный ограниченный по времени токен. Токен сохраняется только в
`sessionStorage` вкладки и удаляется при выходе. Приватные комнаты по-прежнему
вмещают до восьми человек.

По умолчанию `M480_MAX_CONNECTIONS=0` и `M480_HTTP_CONCURRENCY=0`: фиксированного
общего ограничения подключений нет. При необходимости администратор может
задать положительные значения. Реальная вместимость зависит от CPU, памяти
и пропускной способности; защита входа, лимиты сообщений и ограниченные
очереди медленных клиентов продолжают работать. Нагрузочное тестирование
этой версии не проводилось.

Клиент создаёт комнату с `mode: "city"`. Она доступна для входа сразу,
без отдельной трёхминутной гонки. Сервер передаёт положение маршруток,
проверяет форму пакетов, границы значений и правдоподобность перемещения.
Расчёт своей маршрутки остаётся на клиенте, поэтому сетевой RTT не
задерживает руль и педали. Обычные машины NPC рассчитываются на сервере,
а клиент получает ближайших участников одного общего мира. Компактный
граф `assets/irkutsk-traffic.json.gz` загружается один раз для всех комнат.
Карьера и пассажиры остаются личными; клиентские
деньги не принимаются в серверный рейтинг.

Совместимость старого протокола `arcade` сохранена для существующих клиентов
и данных, но новый интерфейс создаёт и показывает только комнаты `city`.
